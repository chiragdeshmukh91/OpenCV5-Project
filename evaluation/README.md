# CLEARPATH evaluation

Every number in this document comes from a script in this repository, run on the machine named next to it. The
scripts write JSON into `evaluation/results/` and `backend/eval/results/`. Metrics we could not measure with the data
available are listed as **Pending**, not estimated.

## Data used

| Data | What it is | Ground truth | Rights / privacy |
|---|---|---|---|
| 14 synthetic clips (`backend/footage/*.avi`, 40 frames, 10 fps, 768×576) | Generated by `backend/scripts/generate_footage.py`. Real pedestrian sprites are cut from OpenCV's public sample `vtest.avi` and re-composited onto a background plate with a controlled count, direction and speed. Degradations: smoke/haze, lens tampering, frozen feed. | Exact, written by the generator: behaviour, people count and flight direction (`manifest.json`), plus per-frame boxes and per-agent speed (`<clip>.gt.json`). | OpenCV sample data. Pedestrians are anonymous, and no school or student imagery is used. |
| `backend/assets/vtest.avi` (unmodified, first 60 frames) | Real public OpenCV sample footage | Behaviour only ("ordinary walking"), judged visually. No box labels. | As above |
| 4 scenarios (`backend/clearpath/data/scenarios.json`) | A simulated report plus a clip assigned to each of 7 cameras in a fictional school | Expected recommendation (`expected`) | Fictional |

**What this data cannot show:**

* **Real-world accuracy.** No real school footage, labelled incident footage or calibrated camera installation was
  available, and none should be collected without consent.
* **Firearm detection.** No clip contains a weapon, and YOLOX-S (COCO-80) has no firearm class.

## How to reproduce

The commands below run from the repository root with the backend virtualenv active, after
`python backend/scripts/generate_footage.py` has been run.

```bash
python backend/eval/run_eval.py              # perception vs generation labels, agent recommendations (~5 min)
python evaluation/run_detection_eval.py      # frame-level detection, running tracks, false alerts, timing (~8 min)
python evaluation/run_review_consistency.py  # location attribution + human-review state invariants (~5 min)
```

The footage generator is deterministic: regenerating produced frame-identical clips (14/14, checked by hashing the
decoded frames). Timings depend on the CPU.

## Metrics and results

Run on x86_64, Intel Xeon @ 2.80 GHz, 2 vCPU, OpenCV 5.0.0, YOLOX-S `yolox_s_2022nov.onnx`, confidence 0.35, on
2026-10-26. Detailed results:

* `evaluation/results/detection-x86_64-*.json`
* `evaluation/results/review-x86_64-*.json`
* `backend/eval/results/eval-x86_64-*.json` and `docs/EVALUATION_RESULTS.md`

### 1. Person detection, frame level (synthetic composites)

Every frame of every clip goes through `cv.dnn` YOLOX-S. Detections are matched one-to-one to ground-truth sprite
boxes. Ground-truth boxes less than half inside the frame are treated as "ignore" regions: they count as neither a hit
nor a miss.

| Condition | IoU ≥ 0.5: P / R / F1 | IoU ≥ 0.75: P / R / F1 | GT boxes |
|---|---|---|---|
| Clean frames (12 clips) | 0.970 / 0.932 / 0.951 | 0.897 / 0.864 / 0.880 | 2,330 |
| Smoke (haze) frames | 0.992 / 0.979 / 0.985 | 0.983 / 0.971 / 0.977 | 242 |
| Lens covered (tampered clip, after tampering) | — / 0.000 / — | — / 0.000 / — | 137 |
| Background plate alone (residual people) | 0 person detections | | |

**Important bias:** the sprites were cut out using this same detector (score ≥ 0.8), so recall here is
**optimistic**. These numbers check the pipeline's decoding, NMS and box mapping on known inputs. They are not an
estimate of detection quality on new footage.

### 2. "Running" track classification

Each tracked person is mapped to a ground-truth sprite by majority IoU match. The pipeline's running flag (track speed
> 2.0 body-heights/s) is then compared with the sprite's true speed.

| Tracks | TP | FP | FN | TN | Precision | Recall |
|---|---|---|---|---|---|---|
| 92 (91 matched) | 29 | 1 | 6 | 55 | 0.967 | 0.829 |

### 3. Candidate events (false alerts), clip level

A candidate event is a clip interpreted as `flight` or `agitated`, or one with a weapon-like COCO object. The
dehaze re-run that the agent itself performs is included. Truth: the clip was generated as `flight`.

| Flight clips flagged | Non-flight clips flagged (false alerts) | False-alert rate |
|---|---|---|
| 4 / 4 | 0 / 10 | 0.0 (10 clips) |

The clip-level activity result is 15/15 correct (`backend/eval/run_eval.py`): calm, flight with the correct direction,
empty, congested, frozen, obstructed, haze then dehaze, and the unmodified `vtest.avi` judged calm.

The first two rows check that the attribution rule behaves consistently. They are not location accuracy. Every clip
here is replayed sample footage, so "unknown" is the correct output for every clip.

### 5. Human-review state consistency

`run_review_consistency.py` drives the real agent through each scenario with a scripted reviewer: dismiss one candidate
event, confirm the rest, reject the recommendation, then approve. After every step it checks these invariants:

* review status ↔ location ↔ applied;
* alert zones only where an applied event is located;
* twin location = review-panel location;
* `pending_observations` = the pending set;
* every decision is in `review_history` and in the trace;
* evidence frames are still on disk;
* the belief counts only applied events;
* a rejected option is not re-recommended unless it is flagged as the only feasible option;
* when complete, all actions are logged as `SIMULATED`.

**Result: 160 / 160 checks passed.** An earlier run (158/160) found a real bug: rejecting the only feasible option
(HOLD in S1, LOCKDOWN in S3) re-proposed it without telling the reviewer. It is now flagged with
`no_feasible_alternative`, explained in the UI and trace, and covered by `tests/test_decision.py`.

## Failure cases observed

* **Crowd occlusion** (`congested_exit`, 14 people): P 0.90 / R 0.82 at IoU 0.5. The generator does not model
  occlusion, so overlapping sprites still count as separate ground-truth people.
* **Fragmented tracks in fast flight** (`flight_left_b`, `flight_right_b`): 6 running people were not flagged as
  running. Their tracks were too short or broken by the greedy association. The clip-level label was still correct.
* **A fast walker counted as running** (`normal_c`, track at 2.01 BH/s): the threshold is a hand-set constant. It is
  visible in the evidence review as a red box on a calm clip.
* **Frozen feed:** detection still "works" on the repeated frame, so frozen-feed detection relies on frame
  differencing (`frozen_ratio`), not on DNN output. The clip is correctly marked unusable.
* **Covered lens:** detection drops to zero. The camera is marked faulted and treated as a coverage gap.
* **Location:** every observation's location is unknown until a human confirms it. A confirmation is the reviewer's
  assertion, not a measurement.
